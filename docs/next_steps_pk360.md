# План работ по проекту «Приемная кампания 360»

## Задача 1. Доступ к данным и обезличивание

**Цель:** получить достаточные данные для ИИ-агента и дашборда, не вынося персональные данные за пределы локального/корпоративного контура.

Что сделано:

- изучена форма заявки `Заявка_на_доступ_к_данным_ИИ-агенты.docx`;
- подготовлен черновик состава данных и формулировок для заявки: `docs/data_access_request_pk360.md`;
- создан локальный обезличиватель: `tools/anonymize_admissions_data.py`;
- создан PowerShell-запускатель: `tools/run_anonymizer.ps1`;
- добавлены правила `.gitignore`, чтобы реальные выгрузки и обезличенные файлы не попали в GitHub случайно;
- скрипт проверен на синтетическом CSV.

Следующие действия:

1. Положить реальную выгрузку в `data/raw/`.
2. Запустить обезличивание.
3. Проверить отчет трансформаций.
4. Использовать обезличенный файл для демо-дашборда.

## Задача 2. Переработка презентации проекта

Новые материалы:

- `ТЗ на презентацию проекта - Вайб-кодинг для руководителей.md`;
- `Политех.Вайб-кодинг для руководителя.Шаблон презентации.pptx`;
- `Разработка ценностного предложения для продукта. Презентация продукта Модуль 4.pdf`.

Требования из ТЗ:

- 10 слайдов;
- 7 минут выступления + 5 минут вопросов;
- единый файл;
- слайд 5 должен вести к демонстрации прототипа;
- обязательно показать экономический эффект, затраты, окупаемость и ROI;
- жюри будет проверять валидацию, реалистичность цифр, архитектуру, безопасность, целостность данных и поддержку после обучения.

Следующий шаг:

- взять текущую презентацию `outputs/Приемная_кампания_360_JTBD_MVP_консультация_v2.pptx`;
- переработать ее под структуру ТЗ на 10 слайдов и шаблон Политеха;
- добавить слайд с экономическим эффектом на основе замера ручной работы и стоимости разработки.

## Задача 3. Docker и публикация

Новый материал:

- `Промпт. Локальная установка Docker и публикация приложения в нём.txt`.

Смысл:

- запускать приложение в контейнере;
- не ставить зависимости на хост;
- подготовить команды `up`, `logs`, `stop`;
- следующий этап - размещение на сервере, где данные будут храниться и обрабатываться внутри согласованного контура.

Следующий шаг:

- не делать сейчас;
- вернуться после подготовки обезличенных данных и версии дашборда;
- затем создать или проверить `Dockerfile` / `docker-compose.yml`.

## Ближайшая практическая последовательность

1. Получить или положить реальную выгрузку в `data/raw/`.
2. Запустить локальное обезличивание.
3. На обезличенных данных собрать демо-датасет для дашборда.
4. Обновить дашборд под данные, близкие к реальным.
5. Переработать презентацию под 10 слайдов защиты.
6. Подготовить GitHub-версию без ПДн.
7. После этого заняться Docker и серверным размещением.
